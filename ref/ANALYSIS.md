# 参考视频分析 (ref/ref.mp4, 720x1280 30fps 18.63s)

## 时间轴（帧差检测）
- 0 – 2.77s：无关解压开场（红色爱心滴胶）。**场景切换在 2.80s**（不是 2.0s），玩法 2.80–18.63s。
- 开场带免责声明：底部 `广告素材宣传场景须达到一定条件，触发相关支线玩法`；右侧竖排 `游戏演示画面 模拟画面请勿模仿 无不良引导`（模糊，近似识读）。**玩法段画面中没有任何文字**，因此工具里两条文字默认关闭，可在设置中打开。
- 第一手操作（帧号 = 自 2.80s 起的 g_XXX 编号-1，30fps）：
  - 约 3.3s 笔尖点击右下单螺丝板的螺丝 → 螺丝 **抬起悬停**（4 帧≈0.13s 抬起，侧视可见螺杆、放大、带阴影），保持悬停等待第二次点击。
  - 约 0.35s 后笔点击空孔 → 螺丝 **飞行** 约 7 帧 ≈0.23s（弧线，直线略带上拱），**拧入** 约 3–4 帧 ≈0.12s，轻微回弹。
  - 板上螺丝全部拧走后约 1 帧开始 **板块直线下落**（无旋转），5 帧左右离开原位，加速下落出屏。露出下方底板的孔（底板在每个螺丝位置都有孔）。
- 因此交互是 **两次点击**：先点螺丝（抬起），再点空孔（飞入）。工具默认“两次点击”，可切换“单击自动选孔”。
- 场景全程静止（无镜头运动）。

## 板块掉落时机（v1.2.1 实测）
- 方法：ref.mp4 30fps 逐帧统计薰衣草像素数找掉落事件（3.47/4.47/11.03/12.63/18.47s 附近），放大裁切逐帧确认。
- 例：手腕右侧板，固定它的最后一颗螺丝在 3.967s 被点击拧出；4.067s 起螺丝已离孔悬停；**4.167s 板开始下落**（点击后约 200ms ≈ 6 帧），此时螺丝还在悬停/尚未选择目标孔，更未落孔。
- 结论：只有“坐在孔里”的螺丝固定板；螺丝一拧出（liftDur 140ms + fallDelay 30ms ≈ 170ms，渲染帧对齐后实测 187ms）板即掉落，与目标孔/落孔无关。取消选择（放回原孔）后该螺丝重新参与固定。
- 工具对照：screenshots/fall_timing_ref_vs_tool.jpg（点击后 0/67/133/167/200/267/333ms），test/fall-timing.mjs 输出 fallAfterLiftMs。
- 绘制顺序：悬停/飞行螺丝绘制在下落板之上。

观察与结论：
- 板块：参考中心 #bdb5ea，边缘有很强的白色光泽边（p95 ≈ #fef9ff），排线对比强（亮度 sd 51）；描边近黑紫 #241426 约 2px；厚度边几乎不可见；描边外有一圈浅色光晕（halo p95 #90a595 vs 背景 #668572）。
- 缝：参考缝内露出浅粉底板（#97888d），v1.2.1 被厚度边+粗描边填成暗色 #60424f。
- 螺丝：参考是拉丝银（扇形明暗交替，主体 #9f9ac2，高光近白），只有一圈细暗边 #30274d（无内圈），十字槽细且偏 x 形（#221f40，臂长≈0.56R）。v1.2.1 螺帽太亮且十字粗。
- 空孔：内部深红棕 #2c160f，下缘奶白斜面月牙；v1.2.1 是黑色描边的平孔。
- 底板：中位 #be8980 与工具一致；参考亮笔触强（p95 #ebc4c6）而暗笔触弱（p10 #b07b71）；描边处取样落在背景色 → 参考底板比描绘多边形略小，手指处几乎无粉色露边（板边到底板边中位 4~5px）→ 参考关卡底板内缩 3px。
- 投影：参考底板下方背景与远处几乎相同（#668371 vs #668572），投影极弱 → plateShadow 0.25→0.18。
- 未完全对齐：板块排线对比（sd 29 vs 51，参考是视频压缩+手绘纹理，再加强会显脏）；螺丝 p95 高光 #e5e3f1 < #fdfaff；底板亮笔触 sd 10.6 vs 17.3；手腕底部形状（几何，非材质）。

## 物理反馈（v1.4 重新逐帧分析，推翻 v1.2.1 “拧出 200ms 即掉落”的结论）
- 方法：`ffmpeg -ss 2.8 -t 6.4 -vf fps=30` 全帧（f1=2.800s，fN=2.8+(N-1)/30）+ 10.0–13.4s；放大裁切逐帧看（tools/ref_physics_strip.py → screenshots/ref_physics_frames.jpg）；
  板位姿用模板配准：参考帧中该板多边形（去掉螺丝头）作模板，逐帧搜索 旋转θ+平移(dx,dy) 使掩膜内中位色差最小（tools/track_plate_rot.py，θ>0=屏幕顺时针，绕板质心）；单钉摆动另用“绕剩余螺丝旋转”搜索复核。
- v1.2.1 错误原因：把第一手的 **第二次点击(3.80s)** 当成了 3.97s 的第一次点击。实际第一次点击是 3.333s。

- 方向：右端（失去螺丝的一端）下垂，即绕剩余钉顺时针 = 重力方向。不是垂到竖直，而是快速下垂到约 17° 后停住（像被下方挡住/角度限位），几乎无阻尼振荡。
- 其后 6.3–8.4s 玩家多次把该板剩余钉拧起又放回（取消），**悬停期间摆动板保持 16.75° 不动**，放回后也不动。

### 最后一颗螺丝离板（10.0–11.0s，左手腕单螺丝板 plate24，钉 327,808，质心在钉左约 9px）
- 螺丝悬停期间（10.40s 起）板不动；螺丝飞到右上空孔，f20/f21(10.633–10.667) 落座。
- 10.700s（落座后 1 帧）开始下落：dy = 5, 12.5, 25, 41.5, 61.5, 85.5, 114, 146 px → ≈3600 px/s²；
  θ = −2, −3.25, −6.5, −9, −11.5, −14, −18, −20.25°（逆时针 ≈ −75°/s，略加速）→ 有力矩时（质心偏离最后一颗钉）板以该钉为支点开始转并带着角速度下落；dx 仅 −0.5 px/帧。
- 掉落板在其它板之上，不与其它板碰撞，直接加速出屏（约 8–9 帧离开底板区）。
- 2.8–13.4s 内没有出现“摆动中的双钉板再拧走最后一颗”的画面；工具按同一规则：最后一颗钉落座后释放，保留当前角速度 + 重力下落。

### 结论（工具实现目标）
1. 板的“钉”释放时机 = **被拧走的螺丝在目标孔落座完成后 ~1–2 帧（33–67ms）**；第一次点击/悬停/飞行期间板一律不动（逻辑上的阻挡判定仍按“坐在孔里”算，但视觉反馈延迟到落座）。取消（放回原孔）没有任何反馈。
2. 剩 1 颗钉：绕该钉向重力方向下垂，~100ms 内到 ~17°（角加速度 ~4500°/s²），硬停、几乎不回弹，之后保持。
3. 0 颗钉：重力 ~3600 px/s² 下落，初始角速度来自最后一颗钉相对质心的力矩（偏 9px ≈ −75°/s），无碰撞，出屏。

### 螺丝动画时长复核（v1.4.1）
- 抬起：第一手 f16→f19（tap 后 ~3 帧≈100ms 到悬停高度），第二手 f63→f67（~133ms）→ liftDur 120ms。悬停高度：螺帽中心约在孔上方 40px（工具 liftH=22，未改）。
- 悬停：第二手 f67–f74 螺帽高光质心漂移 ≤0.3px，**完全静止、不浮动、不旋转** → hoverBob 0。

## 孔位与对齐（v1.5，回应“板掉一半还能把螺丝放回去”）
- 参考 2.8–9.0s 逐帧复核（9.07s 起画面切到新一局完整关卡）：
  - 粉色底板在每个螺丝位置都有孔，板被拧走/掉落后露出的是**底板上原位置的孔**（手腕孔 452,806 在第一手掉落后露出，第二手螺丝正是拧进这个底板孔）。
  - 双钉板(plate22)绕左钉摆到 16.75° 后，它的右孔随板移到约 (495,770)，而底板孔 (482,757) 原位不动、被摆动板的材料**部分盖住**（5.93s 帧：只露出一个月牙）。板孔与底板孔错开。
  - 摆动后到切场前，参考里**没有任何螺丝被放进摆动板的孔或被它盖住的底板孔**；玩家只把剩余支点螺丝拧起又放回（取消）。下落中的板上也从未放过螺丝。
- 工具规则（v1.5）：可放螺丝的孔 = 底板孔（固定）；放入条件 = 此刻覆盖该点的每块板都有自己的孔对准它（容差 6px ≈ 螺丝半径×0.3），没有实心材料盖住；摆动板的错位孔、下落中/已掉落的板不提供任何孔位；摆动板边缘离孔心 <9px 也算压住。逻辑里板由多钉减到 1 钉即按 ±swingMax（17°，与画面一致）绕剩余钉旋转，用旋转后的轮廓/孔位判断覆盖与对齐（求解器/生成器同一规则）。对照：screenshots/hole_alignment.jpg。
